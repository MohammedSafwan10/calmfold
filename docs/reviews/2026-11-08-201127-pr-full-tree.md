# Keepstone foundation: notes, tasks, storage, crypto, and the GPUI shell

This is a review of the whole tree at commit 48c5e8f. The app is a local-first GPUI desktop client over a single SQLite store, with domain rules in `keepstone-core`, persistence and FTS5 search in `keepstone-storage`, a vault crypto crate that no feature uses yet, and a shell that sends every command through app-level actions. The layering is clean, and core is strict about its rules: the task state machine is tested as an exact table, `completed_at` is repaired on load, trashed entities reject edits, and timestamps never move backwards. The real risks are in the notes editor's save lifecycle. Typing can be silently thrown away on quit, and also when a save fails and the user moves to another note. `cargo test --workspace` passes.

Watch for: unsaved typing is lost on quit or window close (no flush hook, **confirmed**); a failed save followed by opening another note overwrites the unsaved text (**confirmed**); a title over 300 characters blocks all body saves (**confirmed**); "New note" or "New task" chosen from the palette probably loses the input focus it just set (**likely**).

**Verdict**: NEEDS_CHANGES

## High-level view

The editor is built as an Empty → Clean → Dirty machine with a 500 ms debounce, and it flushes on blur, on switching notes, and on trashing. Two gaps let the Dirty state end without a save. The app has no quit or close hook, so a pending debounce is simply dropped. And `open_note` and `new_note` keep going after `flush` fails, so they replace the editor contents with the stored version. The module docs say "save error: stays Dirty", but the code clears the dirty flag anyway.

Validation errors from core reach the editor every 500 ms as toasts. A title longer than 300 characters makes every save fail, body included, which feeds straight into the overwrite problem above.

The command palette's `IndexPath` mapping is correct. gpui-component reports the original section and row, and the Notes group is only added when it has items, so section 1 is always Notes. The palette's real problem is ordering. `close_dialog` restores the focus that was saved when the palette opened, and it runs after the deferred `with_shell` command, so it undoes the focus that `new_note` or `new_task` just set.

The sidebar's element id includes the current width, which keeps drag resizing free of animation lag. It also re-keys every piece of keyed state inside the sidebar on every resize, including which submenus are expanded and the scroll position.

Storage is careful. Upserts keep `created_at`, the FTS triggers stay in sync on upsert and delete, links are rewritten inside a transaction, and `fts_query` quotes every term. Three weaker spots remain. `notes` uses an implicit rowid as the FTS content key, which a VACUUM can renumber. One corrupt row fails a whole list, and the UI then shows the "No notes yet" empty state. `find_note_by_title` compares with SQLite's ASCII-only `lower()`.

The crypto crate is sound: Argon2id parameters are bounded on both sides, the 24-byte nonce is random, the header and a length-prefixed AAD are authenticated, keys are zeroized, and errors reveal nothing. No issues need fixing before the vault is built on it.

Smaller state-machine gaps: the task menu offers Start and Cancel on closed tasks, which the core then rejects. The "System" reduce-motion setting is read once at startup. Appearance save failures are only written to stderr.

4. **Error toast every debounce tick** (low, confirmed). Show a save error once per Dirty episode instead of on every 500 ms flush.
5. **Palette close steals focus from New note/New task** (medium, likely). Close the dialog before the command runs. Either drop the action from the item and run it from `on_confirm` after `close_dialog`, or move focus again after the close.
6. **Sidebar re-keyed by width** (low, likely). Use a width-based key only while a drag is in progress, then go back to a stable id. Alternatively, keep the stable id and accept the animation during drags.

## Editor save lifecycle in `views/notes.rs`

The debounce is a `Task` stored in `pending_save` (lines 231-242). Replacing that task cancels the earlier timer, and `flush` (244-273) writes through `Library::edit_note`. Inside the running app this works, and `switching_notes_flushes_unsaved_typing` covers the case where the save succeeds.

**Quit loses the last half second (confirmed).** `Quit` is bound to `cx.quit()` (`actions.rs:68-70`), and nothing registers `on_app_quit` or a should-close handler. When the user types and then presses ⌘Q or closes the window within 500 ms, `pending_save` is dropped along with the view and the text is never written. Pressing ⌘Q quickly after typing is common, so this is the most likely way for users to lose data. Fix: in `start`, register `cx.on_app_quit(|cx| ...)` to update the shell, call `notes.flush` and `layout.save`, and also handle `on_window_should_close`. `flush` needs a `Window` only for the error toast, so give it a variant that only logs.

**A failed flush followed by a switch drops the edits (confirmed).** `open_note` (147-183) calls `self.flush(...)` and ignores whether it worked. It then calls `set_value` on title and body with the stored note and sets `self.dirty = false` (181). `new_note` (133-145) does the same through `open_note`. `set_show_trash` and `trash_open` flush and then move on as well. Any save error (a title that is too long, a body over 2 MiB, a SQLite `busy` or disk-full error) therefore ends with the unsaved text replaced by what was last stored. This contradicts the "stays Dirty, user notified" promise in the module docs. Clicking the row of the note that is already open shows the same problem, because it reloads from the database.

```rust
// minimal fix
fn flush(&mut self, ...) -> bool { ... }          // true when clean afterwards
pub fn open_note(...) { if !self.flush(window, cx) { return; } ... }
```

**Title validation blocks the body (confirmed).** The title `Input` has no length limit. `Note::edit` checks the title before it saves anything, so when the title is longer than 300 characters every flush returns `TitleTooLong`, body edits pile up unsaved, and a toast appears on every debounce tick and every blur. Combined with the overwrite problem, switching notes loses all of it. Limit the input to `MAX_TITLE_CHARS`, or save the body under the previous valid title.

The title shown in the editor and the title stored agree. `flush` computes `saved_title` with the same `normalize_title` → `UNTITLED` fallback as `note_title`, so backlinks are reloaded exactly when the stored title changes. `set_value` emits no `InputEvent::Change` (checked in `gpui-base` `input/base/state.rs:1252`), so opening a note does not mark it dirty.

## Command palette ordering in `shell.rs`

When an item is confirmed, gpui-component dispatches the item's `Action` and then defers `on_confirm` (`command/state.rs:617-636`). The app-level handler calls `with_shell`, which uses `cx.defer`, so the order is: shell command runs → `on_confirm` → `window.close_dialog(cx)` (`shell.rs:325-326`). `close_dialog` focuses the dialog's `previous_focused_handle` synchronously (`root.rs` `close_dialog`). After "New note" from the palette, focus therefore leaves the new title input. After "New task", it leaves the quick-add field. The existing palette test only checks that Escape closes the palette. Fix: run palette commands from `on_confirm` after closing the dialog, and leave the `.action()` on items only for the shortcut hint, if gpui-component allows that. Otherwise, move focus again in a `window.defer` after the close.

## Sidebar keyed by width

`Sidebar::new(format!("main-sidebar-{}", width))` (`shell.rs:431-434`) is the parent element id of every `use_keyed_state` inside the sidebar: `{id}-list-state`, `{id}-anim-w`, and each submenu's open state (`sidebar/menu.rs:279`). Every resize step creates fresh state. The visible effects are that submenus the user expanded or collapsed go back to `default_open(self.route == route)`, and the scroll position resets. Collapse and expand still animate, because the width does not change while collapsing. The layout save is debounced to 300 ms and has the same quit gap as the notes autosave. `layout.json` is written to a temp file and renamed without an `fsync`, unlike `appearance.json`. A crash would only reset the layout to defaults, because `load` falls back.

## Task status in the UI and core

The rules in `core/src/task.rs` hold. Same-state moves are no-ops, failed transitions change nothing, `completed_at` is set exactly when the status is `Done` (and `from_parts` repairs it), and trash rejects every change. The UI does not follow those rules. `task_row.rs:186-187` always shows "Start" and "Cancel task", including on Done and Cancelled rows in the Done tab, and `transition` rejects those with an `InvalidTransition` error toast. No menu item offers InProgress → Todo. `tasks.rs:121` gives a due date only on the Today tab, so a task added on Upcoming disappears from the list the user is looking at. `TasksView.today` and the sidebar badge are only refreshed by a reload or a `TasksChanged` event, so they show yesterday's date and counts after midnight until something changes.

## Storage edge cases

`notes` has a TEXT primary key and an implicit rowid, and `notes_fts` uses `content_rowid = 'rowid'` (`0001_init.sql:6-25`). SQLite allows VACUUM to renumber implicit rowids. If a VACUUM ever runs (a future "compact" command, or a user running sqlite3), search results would join to the wrong notes. Nothing runs VACUUM today, so this is latent. Fix it in the migration that next rebuilds `notes`, or run `INSERT INTO notes_fts(notes_fts) VALUES('rebuild')` after any VACUUM.

`collect_summaries` (`notes.rs:211`) and `list_tasks` (`tasks.rs:118`) return the first `Corrupt` error for the whole query. The views only `eprintln` the error (`notes.rs:212`, `tasks.rs:110`), and Today uses `unwrap_or_default`, so one bad row makes every note or task look gone, with the "No notes yet" empty state on screen. This breaks the AGENTS rule that every screen needs an error state.

`find_note_by_title` matches Rust's `to_lowercase()` key against SQLite's `lower(title)` (`notes.rs:128`). SQLite's `lower()` only folds ASCII, so a note titled "Ölwechsel" or "МАШИНА" is never found. Backlinks are not affected, because both sides use `normalize_target`. The function has no caller yet.

The upserts keep `created_at` because it is left out of `DO UPDATE SET`. The `AFTER UPDATE OF title, body` trigger fires on every upsert, so pinning and trashing also re-index the note in FTS. That costs some work and does no harm.

## Appearance

`system_reduce_motion` is read once in `init` (`appearance.rs:176`). It has to be captured before the override, but the result is that "System" never follows a change made in the OS while the app is running. A failed save is reported only on stderr (`appearance.rs:202`), while the in-memory setting has already changed, so the user loses it on the next launch without being told.

## Security posture

FTS input is bound as a parameter, and every term is quoted with `"` doubled (`codec.rs:40-46`). The tests include hostile input. No SQL is built from user strings. Logs and toasts contain only domain and storage error messages, which name columns and never include values. In the crypto crate, Argon2id is pinned to v0x13, parameters are bounded at 19 MiB–1 GiB, t=2–64 and p=1–16, the 16-byte salt and 24-byte nonce come from `getrandom`, `[KS][v1]` plus a length-prefixed caller AAD is authenticated, and `SecretKey` and the plaintext returned by `open` are zeroized. XChaCha20-Poly1305 is not key-committing. That matters only if the vault ever tries several candidate keys against one ciphertext, so plan the vault header to authenticate a key check value.

## Test coverage

Not tested: a save failure followed by a note switch, quit or close while Dirty, a title over 300 characters, focus after a palette command, sidebar state across resizes, task menu items on closed tasks, error states for a corrupt row, and FTS consistency after VACUUM.
